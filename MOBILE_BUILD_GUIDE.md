# HuatPick — Mobile App (Capacitor) Build Guide

This document walks you through turning the HuatPick web app into installable
**Android (.aab / .apk)** and **iOS (.ipa)** apps for the Google Play Store and
Apple App Store.

The web app is already wrapped with [Capacitor](https://capacitorjs.com) and
both native projects are scaffolded at:

```
/app/frontend/
├── capacitor.config.ts      # mobile-app config
├── build/                   # React production bundle (regenerated by `yarn build`)
├── android/                 # ✅ Android Studio project — open this in Android Studio
└── ios/                     # ✅ Xcode workspace — open `ios/App/App.xcworkspace`
```

> ℹ️ The Linux container that runs the preview cannot produce signed `.aab` or
> `.ipa` files — those need Android Studio / Xcode on your own machine.
> What's bundled here is the **complete native source** ready to open.

---

## 1. Prerequisites (on your local machine)

### For Android
- [Android Studio](https://developer.android.com/studio) (Hedgehog or newer)
- Android SDK 33 or newer (Android Studio installs this for you)
- A free [Google Play Developer account](https://play.google.com/console) ($25 one-time fee)

### For iOS
- A **Mac** running macOS 13 or newer
- [Xcode 15+](https://apps.apple.com/app/xcode/id497799835)
- [CocoaPods](https://cocoapods.org/) (`sudo gem install cocoapods`)
- An [Apple Developer account](https://developer.apple.com/programs/) ($99/year)

### For both
- Node 18 + Yarn 1.22 (matching this project)

## 2. One-time setup

```bash
# clone your repo to your local machine, then:
cd huatpick/frontend
yarn install
```

Make sure `frontend/.env` has the **production** backend URL:

```env
REACT_APP_BACKEND_URL=https://<your-deployed-emergent-url>
```

Build the web bundle and sync it into both platforms:

```bash
yarn cap:sync          # builds React + syncs to android/ and ios/
```

---

## 3. Build & test on Android

```bash
yarn cap:android       # builds + opens Android Studio
```

Inside Android Studio:
1. Wait for Gradle to finish syncing (first run takes a few minutes).
2. Plug in an Android phone (USB debugging enabled) **or** start an emulator.
3. Press the green ▶ button to install + run.

To produce a **release `.aab`** for Play Store:
1. `Build` → `Generate Signed Bundle / APK` → `Android App Bundle`.
2. Create or select your **upload keystore** (keep this file safe forever —
   losing it means losing access to your Play Store listing).
3. Pick `release` build variant.
4. Output lands in `android/app/release/app-release.aab`.

Upload that file to the Play Console → Release → Production → Create release.

---

## 4. Build & test on iOS (Mac only)

```bash
yarn cap:ios           # builds + opens Xcode workspace
# When Xcode opens, it should be `ios/App/App.xcworkspace` (NOT `App.xcodeproj`)
```

In Xcode:
1. Select the `App` target → `Signing & Capabilities`.
2. Pick your Apple Developer team. Xcode auto-creates a provisioning profile.
3. Pick an iPhone or simulator from the device dropdown.
4. Press ▶ to run.

To produce an **`.ipa` for App Store Connect**:
1. Select `Any iOS Device (arm64)` as the destination.
2. `Product` → `Archive`.
3. When the Organizer opens, click `Distribute App` → `App Store Connect` → `Upload`.

Then go to App Store Connect → My Apps → Create New App → fill in metadata.

## 5. App identity

Edit `/app/frontend/capacitor.config.ts` if you want to change:

| Field | Current value | Used in |
|---|---|---|
| `appId` | `com.huatpick.app` | Android `package` / iOS Bundle ID |
| `appName` | `HuatPick` | App icon label |
| `webDir` | `build` | Source web bundle |

After editing, re-run `yarn cap:sync`.

> ℹ️ **About `com.huatpick.app`**: You do **not** need to own the domain `huatpick.com`
> to use this appId. Both Play Store and App Store only require that the bundle ID is
> unique within their own systems. If `com.huatpick.app` is already taken when you
> upload, change it to something like `com.jhcreative.huatpick` and re-sync.

### Required for Play Store / App Store listings
| Field | Value |
|---|---|
| **Developer name** | JH Creative Enterprise |
| **Support email** | turyoungpotato@gmail.com |
| **Privacy Policy URL** | `https://<your-deployed-url>/privacy` |
| **Terms of Service URL** | `https://<your-deployed-url>/terms` |
| **Age rating** | 18+ (gambling-adjacent content; lottery suggestions) |
| **Content rating IARC questionnaire** | Answer "simulated gambling: no" (we suggest numbers, we don't take bets) |

Both legal pages are already built into the app and publicly accessible without
login at `/privacy` and `/terms` — both URLs get crawled by the stores when you
paste them into the listing.

### App icon & splash screen
Replace the placeholder assets:

- **Android**: `android/app/src/main/res/mipmap-*/ic_launcher*.png`
  - Recommended: use Android Studio's `Image Asset` wizard (right-click `res` → New → Image Asset).
- **iOS**: `ios/App/App/Assets.xcassets/AppIcon.appiconset/`
- **Splash**: `android/app/src/main/res/drawable*/splash.png`, `ios/App/App/Assets.xcassets/Splash.imageset/`

The fastest way to generate all the sizes from a single 1024×1024 PNG is the
[`@capacitor/assets`](https://github.com/ionic-team/capacitor-assets) tool:

```bash
yarn add -D @capacitor/assets
# Create a square 1024x1024 icon at resources/icon.png + 2732x2732 splash at resources/splash.png
npx capacitor-assets generate
```

## 6. App architecture (how the web ↔ native communicate)

- The native shell loads the bundled `build/` folder via `file://` (offline-friendly).
- All `/api/*` requests still go to your **deployed backend** via
  `REACT_APP_BACKEND_URL` baked in at build time.
- Stripe checkout, push notifications, etc. all work because the WebView is
  a real Chromium/WebKit instance.
- Switching to a "remote-load" model (web app loaded from your server, so
  updates ship instantly without store re-submission) is one config flip:

  Uncomment the `server` block in `capacitor.config.ts` and re-sync.

---

## 7. Updating after code changes

Every time you change React/CSS code:

```bash
yarn cap:sync
```

…then re-build in Android Studio / Xcode. For web-only content updates with
the remote-load mode enabled, no sync is required — the app picks up changes
from your deployed Emergent URL on next launch.

## 8. Cloud build alternatives

If you do not have a Mac (for iOS) or just want hands-off CI builds, consider:

- **Codemagic** — free tier, supports both iOS and Android Capacitor builds
- **Bitrise** — generous free tier for hobbyists
- **Ionic Appflow** — official Capacitor cloud build service
- **GitHub Actions** — free for public repos; uses macOS runners for iOS

A starter `.github/workflows/mobile.yml` could:
1. Checkout
2. `yarn install && yarn cap:sync`
3. Build Android: `cd android && ./gradlew bundleRelease`
4. Upload artifact

Ask me if you'd like a ready-made GitHub Actions workflow committed to the repo.

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| Gradle won't sync, "JAVA_HOME not set" | Install JDK 17 → set `JAVA_HOME` env var |
| "CocoaPods not installed" when running `cap:ios` | `sudo gem install cocoapods && pod setup` |
| API calls fail in the native app | Check `REACT_APP_BACKEND_URL` in `frontend/.env` — must be a **public HTTPS URL**, not localhost |
| App rejected for missing privacy policy | Add a hosted privacy-policy URL to Play Console / App Store Connect listing |
| Stripe checkout opens browser then doesn't return | Add the universal link / app link config (see Capacitor's `App.addListener('appUrlOpen')` docs) |

| Command | What it does |
|---|---|
| `yarn build` | Build React production bundle into `build/` |
| `yarn cap:sync` | Build + copy assets into `android/` and `ios/` |
| `yarn cap:android` | Build + open Android Studio |
| `yarn cap:ios` | Build + open Xcode workspace |
| `yarn cap:run:android` | Build + auto-run on a connected Android device |
